\chapter*{Tóm tắt}
\addcontentsline{toc}{chapter}{Tóm tắt}

DocVault là một hệ thống quản lý tài liệu bảo mật được xây dựng theo kiến trúc microservices, hướng đến bài toán quản lý vòng đời tài liệu trong môi trường có yêu cầu phân quyền, kiểm soát tải xuống, lưu vết audit và hỗ trợ compliance. Hệ thống cho phép người dùng tạo tài liệu, tải lên phiên bản file, gửi duyệt, phê duyệt, xuất bản, lưu trữ và truy vết các hoạt động liên quan. Các vai trò chính gồm Viewer, Editor, Approver, Compliance Officer và Admin. Mỗi vai trò có phạm vi truy cập khác nhau dựa trên RBAC, ACL, trạng thái tài liệu và mức phân loại bảo mật.

Về mặt ứng dụng, DocVault được triển khai với frontend Next.js, API Gateway và các backend service NestJS gồm metadata-service, document-service, workflow-service, audit-service và notification-service. Hệ thống sử dụng Keycloak cho xác thực, PostgreSQL cho metadata, MongoDB cho audit log và MinIO/S3 cho lưu trữ file. Các kiểm soát bảo mật trọng tâm bao gồm phân quyền theo vai trò, ACL deny-overrides, kiểm soát preview/download, grant token ngắn hạn, hash-chain audit, malware scanning, DLP, retention evidence và compliance evidence packet.

Về mặt DevSecOps, đề tài thiết kế và triển khai pipeline Jenkins nhằm tự động hóa các bước cài đặt phụ thuộc, kiểm thử, SAST, SCA, quét filesystem/image bằng Trivy, quét IaC bằng Checkov, validate Terraform, build Docker image, cập nhật GitOps branch, kiểm tra Argo CD health, smoke test sau triển khai và DAST bằng OWASP ZAP. Cả hợp phần ứng dụng và hợp phần DevSecOps đều đã được hiện thực và có bằng chứng vận hành; các nội dung còn lại tập trung vào gia cố vận hành ở quy mô production như chuẩn hóa provenance, bắt buộc xác minh chữ ký tại admission và diễn tập khôi phục dữ liệu.

\textbf{Từ khóa:} DocVault, quản lý tài liệu, bảo mật ứng dụng, microservices, DevSecOps, RBAC, ACL, audit, DLP, Jenkins, GitOps.

\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}

DocVault is a secure document management system designed around a microservices architecture and a DevSecOps-oriented delivery process. The system addresses document lifecycle management in an environment that requires role-based access control, controlled file access, auditability, and compliance evidence. Core workflows include document creation, file upload and versioning, review submission, approval, publication, archiving, preview/download authorization, audit inspection, and evidence export.

The application layer consists of a Next.js frontend, an API Gateway, and NestJS microservices, including metadata, document, workflow, audit, and notification services. Keycloak provides identity and access management, PostgreSQL stores document metadata, MongoDB stores audit events, and MinIO/S3 stores file objects. Security controls include RBAC, ACL with deny-overrides semantics, short-lived grant tokens, tamper-evident audit hash chains, malware scanning, DLP classification escalation, retention evidence, and compliance evidence packets.

The DevSecOps pipeline is implemented with Jenkins and integrates security checks throughout the build and deployment process. It includes dependency analysis, static application security testing, filesystem and image scanning, infrastructure-as-code scanning, Terraform validation, unit testing, Docker image build and scan, GitOps updates, Argo CD health checks, post-deploy smoke tests, and OWASP ZAP DAST. Both the application and DevSecOps scopes are implemented and backed by operational evidence; the remaining work focuses on production-grade operational hardening, such as standardized provenance, admission-time signature enforcement, and data recovery drills.

\textbf{Keywords:} DocVault, document management, application security, microservices, DevSecOps, RBAC, ACL, audit, DLP, Jenkins, GitOps.
